# Todo App

A React + TypeScript app covering lifted state, effects with cleanup, data fetching with four UI states, and client-side routing.

## Features

- **Todos with a title and a status** — each todo is `{ id, title, status }`, where status is **To Do**, **In Progress** or **Done**.
- **Full CRUD in local state only** (no backend) — create, list and filter by status, edit the title, change the status, delete, and clear done. All of it lives in `useState` inside `src/features/todos/use-todos.ts`.
- **Username and account section** — the header shows the current user's avatar and `@username`, and `/account` shows the profile (name, username, email, bio) with an editable form and a per-status todo summary.
- **Lifted state** — todos and the account live in `AppLayout` and reach pages through the router's outlet context, so they survive navigating between pages. (Reloading the browser resets them, since nothing is persisted.)

**Repository:** `https://github.com/Sothcheat/todo-app.git` — the app runs from `main`.

## Stack

Vite · React 19 · TypeScript · React Router · Tailwind CSS v4 · shadcn/ui · Biome (lint + format)

## Getting started

```bash

```

| Script           | Purpose                        |
| ---------------- | ------------------------------ |
| `pnpm dev`       | Start the dev server           |
| `pnpm build`     | Type-check and build           |
| `pnpm check`     | Lint + format with Biome       |

## Routes

| Path         | Page                                                       |
| ------------ | ---------------------------------------------------------- |
| `/`          | Redirects to `/todos`                                      |
| `/todos`     | Todo app — add, edit, set status, delete, filter, clear done |
| `/users`     | User directory fetched from JSONPlaceholder                |
| `/users/:id` | User detail — `id` from `useParams` drives the fetch       |
| `/account`   | Current user's profile — view and edit, todo summary       |
| `*`          | 404 catch-all                                              |

Navigation uses `NavLink` / `Link`, so page changes never reload the browser.

### 3. Effects and their cleanup

| Effect | File | What its cleanup prevents |
| --- | --- | --- |
| Live clock | `src/hooks/use-now.ts` | `clearInterval` stops the one-second timer so it doesn't keep calling `setState` on an unmounted component or stack up a second timer. |
| User directory fetch | `src/features/users/user-directory.tsx` | Setting `cancelled = true` stops a stale or StrictMode-duplicated request from updating state after unmount, which would otherwise flash the empty state or overwrite fresh data. |
| User detail fetch | `src/pages/user-detail-page.tsx` | Setting `cancelled = true` when `id` changes stops a slow request for the previous user from overwriting the current one (race condition). |
| System theme listener¹ | `src/components/theme-provider.tsx` | Removing the `matchMedia` `change` listener stops an old listener from re-applying the system theme after the user picks a fixed one. |
| `d` key theme toggle¹ | `src/components/theme-provider.tsx` | Removing the `keydown` listener keeps duplicate handlers from piling up and toggling the theme more than once per key press. |
| Cross-tab theme sync¹ | `src/components/theme-provider.tsx` | Removing the `storage` listener stops an unmounted provider from reacting to theme changes made in other tabs. |

¹ Generated by the shadcn scaffold, not hand-written.
